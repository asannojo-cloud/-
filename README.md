# 아공노 모바일조합원증

아산시공무원노동조합 조합원을 위한 모바일 조합원증 PWA. 관리자가 Excel 명부를 업로드하면 검증 → 미리보기 → 승인 절차를 거쳐 회원 DB가 갱신되고, 조합원은 로그인 후 본인의 모바일 조합원증을 확인할 수 있다.

설계 배경은 [DESIGN.md](./DESIGN.md) 참고.

## 기술 스택

- Frontend: React 19 + TypeScript + Vite + Tailwind CSS v4 + vite-plugin-pwa
- Backend: Node.js + TypeScript + Express
- DB: PostgreSQL 18
- 인증: httpOnly 세션 쿠키 (connect-pg-simple), bcrypt 비밀번호 해시
- Excel 처리: SheetJS(xlsx)
- 이미지 처리: Sharp
- ZIP 처리: adm-zip (경로 탈출/매직바이트 검증 포함)

## 로컬 개발 환경

### 1. 사전 준비

- Node.js 22+ (개발 환경: v24.19.0으로 검증)
- PostgreSQL 18 (로컬 서비스로 실행 중이어야 함)

### 2. 환경변수

`backend/.env` 파일을 생성한다 (`.env.example` 참고). 최소 다음 값이 필요하다.

```
DATABASE_URL=postgresql://<user>:<password>@localhost:5432/asgongno_membercard
SESSION_SECRET=<임의의 긴 랜덤 문자열>
PORT=4000
FRONTEND_ORIGIN=http://localhost:5173
```

**사진 저장소(선택)**: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` 4개를 모두
설정하면 Cloudflare R2(영구 저장)에 사진을 저장한다. 하나라도 비어 있으면 로컬 디스크(`PHOTO_STORAGE_DIR`,
기본 `storage/photos`)에 저장한다 — 로컬 개발은 R2 없이도 그대로 동작한다. **운영 배포(Render 등)에서는
반드시 R2를 설정해야 한다** — 로컬 디스크는 배포/재시작 때마다 초기화되는 경우가 많아 사진이 사라진다
(2026-08-12 실제로 겪은 문제).

DB 계정/DB는 다음과 같이 생성했다 (운영 환경에서도 동일한 패턴 권장 — 앱 전용 계정 사용, `postgres` 슈퍼유저 직접 사용 금지):

```sql
CREATE ROLE asgongno_app LOGIN PASSWORD '...';
CREATE DATABASE asgongno_membercard OWNER asgongno_app;
```

### 3. 설치 및 DB 초기화

```bash
npm install
npm run migrate
npm run seed   # 개발용 가상 데이터만 생성 (실제 조합원 정보 아님)
```

시드 계정:
- 관리자: `admin` / `Admin!2026Dev` (반드시 운영 전 변경)
- 회원 예시: 이름 `홍길동` / 휴대폰번호 `010-0000-0001` (회원 로그인은 이름+휴대폰번호 방식, 회원번호는 관리자 화면에서만 사용)

### 4. 개발 서버 실행

```bash
npm run dev:backend    # http://localhost:4000
npm run dev:frontend   # http://localhost:5173 (백엔드로 /api 프록시)
```

## 배포 방법 (요약)

1. **DB**: 운영 PostgreSQL 인스턴스에 `npm run migrate` 실행 (마이그레이션은 순서대로 1회만 적용됨). 운영 데이터는 `npm run seed`를 실행하지 않고 관리자가 Excel 업로드로 직접 등록한다.
2. **환경변수**: 운영용 `backend/.env`에 강력한 `SESSION_SECRET`, 운영 DB 접속정보를 설정하고 `NODE_ENV=production`으로 지정한다 (세션 쿠키 `secure` 플래그가 자동으로 활성화된다 — 반드시 HTTPS 뒤에 배치).
3. **백엔드 빌드/실행**: `npm run build:backend` 후 `node backend/dist/server.js` (또는 pm2 등 프로세스 매니저 사용).
4. **프론트엔드 빌드**: `npm run build:frontend` → `frontend/dist`를 Nginx 등 정적 서버 또는 백엔드에서 서빙. `/api`는 백엔드로 리버스 프록시한다.
5. **HTTPS**: 리버스 프록시(Nginx/Caddy 등)에서 TLS 종료 후 백엔드로 프록시. PWA와 세션 쿠키 `secure` 옵션 요구사항 상 운영 환경은 반드시 HTTPS여야 한다.
6. **사진 저장소**: Render처럼 배포/재시작 때마다 로컬 디스크가 초기화되는 환경에서는 반드시 `R2_ACCOUNT_ID`/`R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY`/`R2_BUCKET_NAME`을 설정해 Cloudflare R2를 사용한다(2026-08-12부터 적용, 그 전까지는 배포할 때마다 사진이 사라지는 문제가 있었다). 영구 디스크가 보장되는 환경이라면 `PHOTO_STORAGE_DIR`(기본 `storage/photos`)로 로컬 저장도 가능하며, 이 경우 웹 서버의 정적 공개 경로에는 포함시키지 않는다.
7. **백업**: PostgreSQL 정기 백업(`pg_dump`) + (R2 사용 시) R2 버킷 백업 또는 (로컬 저장 시) `storage/photos` 디렉터리 백업을 함께 스케줄링한다.

## 알려진 제한 / 향후 개선

- 관리자 2단계 인증(TOTP)은 DB 스키마(`admins.totp_secret`)만 준비되어 있고 실제 흐름은 미구현 (PRD "가능하다면" 조건부 요구사항).
- QR 코드/공지사항 등 2·3단계 기능은 PRD 42번에 따라 이번 범위에서 제외.

## 변경 이력 (요청 기반 추가 기능)

- 회원 신규 등록 / 상세·수정 화면에서 사진 등록·교체 가능 (매직바이트 검증, 위장파일 차단)
- 회원번호 권장 양식을 "발급연도-일련번호"(예: `2026-1`)로 변경, 신규 등록 시 다음 번호 자동 제안(`GET /api/admin/members/next-id`)
- 회원 화면 상단/회원증에 "조합원증" 라벨과 노동조합 로고 추가
- **(2026-08-12) 회원 로그인 방식을 "회원번호+비밀번호"에서 "이름+휴대폰번호"로 전면 변경.** 1,900명 규모 실제 운영 시 회원번호·임시비밀번호를 개별 전달하는 부담을 없애기 위함. `members.phone`에 UNIQUE 제약을 걸어 동명이인이 있어도 계정이 섞이지 않도록 구조적으로 보장했다 (자세한 배경은 [DESIGN.md](./DESIGN.md) "회원 로그인 방식 변경" 항목 참고). 이에 따라 회원 자가 비밀번호 변경 기능은 제거했다.
- Excel 업로드 컬럼 매핑에 "휴대폰번호" 추가 (선택 항목, 값이 있으면 형식 검증 + 중복 검증)
- 회원검색 창에서 한글 입력 중 Enter가 씹혀 검색이 안 되던 문제 수정 (입력하는 동안 자동 검색으로 전환)
- 생년월일/발급일 입력을 연-월-일 자동 이동 커스텀 컴포넌트로 교체 (부모-자식 값 되돌림 과정에서 로컬 입력이 지워지던 버그 수정)
- 파일 선택(사진, Excel, 사진ZIP) UI를 버튼 스타일로 변경해 시인성 개선
- **Excel 필수/선택 항목 조정**: 이름·휴대폰번호·생년월일만 필수, 회원번호·발급일·사진파일명·상태는 비워도 업로드 가능. 회원번호가 비면 "발급연도-일련번호"로 자동 채번(같은 파일 내 여러 행도 서로 겹치지 않게 순차 부여), 발급일이 비면 업로드일로 채우되 **이미 있는 회원의 발급일은 임의로 덮어쓰지 않음**. 미리보기 화면에 자동채번 여부를 "자동채번" 라벨로 표시
- Excel 관리 화면에 **형식 안내(예시 표) + 양식 다운로드 버튼**(`GET /api/admin/excel/template`) 추가 — 컬럼 구성을 몰라도 바로 받아서 채워 올릴 수 있음
- **회원목록 체크박스 + 일괄 작업 추가**: 전체선택/개별선택 체크박스, "선택 수정"(1명 선택 시 해당 상세화면으로 이동), "선택 삭제"(여러 명 한 번에 삭제 — 비활성 회원만 실제로 삭제되고 활성 회원은 안내와 함께 건너뜀, `POST /api/admin/members/bulk-delete`)
- **회원정보 완전 삭제 기능 추가** — PRD 37 원칙(물리 삭제 금지)을 지키기 위해 **반드시 먼저 "비활성화"된 회원만** 삭제할 수 있도록 제한했다. 삭제 시 화면에 명확한 확인 단계를 거치고, 사진 파일도 함께 정리하며, 삭제 자체도 `audit_logs`에 이름/생년월일/전화번호 스냅샷과 함께 영구 기록되어 "누가 언제 어떤 회원을 삭제했는지"는 삭제 후에도 추적 가능하다.
